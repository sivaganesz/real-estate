# Assumptions — Phase 3 integration

1. **Click-through = drawer, then filtered list.** Reports keeps M1's drill-down drawer (it lists the exact records behind a number). Its "Open in …" button now goes to the module list filtered the same way (`/leads?source=`, `?lostReason=`, `?owner=`, `?stage=booked,converted`; `/pipeline?stage=` for "open in stage", `?stalled=1`; `/properties?status=` / `?type=`). Drills that a URL cannot express (time buckets, the cohort, "ever reached stage X") open the unfiltered list; the drawer stays the exact view for those.
2. **Today charts navigate directly.** The admin source chart opens `/leads?source=<source>`; the manager funnel opens `/pipeline?stage=<stage>` (the deals in that stage now, not everyone who ever reached it).
3. **Link filters are a starting point.** On Leads and Pipeline, once the user edits a filter the link's params are dropped from the URL, so a refresh shows what is on screen. A new filtered link while the page is open replaces the filters.
4. **A `?lostReason=` link implies the Lost stage** (the stage pill shows it) and adds a "Lost reason" pill, shown only when Lost is selected or the reason filter is set.
5. **ModuleAssistant placement.** leadCreate / propertyCreate / appointmentCreate render through `<ModuleAssistant>` in the forms (same paste-and-fill box with voice). followUp on the lead page, propertyEdit on an editable property page, import on `/import`, insights on Reports (all roles) and on manager and executive Today. The admin Today already has M1's insights card, so the shared one is not added twice there.
6. **leadEdit / leadQualify / propertyMatch are not mounted inline a second time.** The lead page's Edit-with-AI and qualification cards (M2) and the matching assistant (M3) do the same jobs on the same AIService calls and are covered by their e2e journeys; duplicating them would show two cards per job. The shared versions are on those pages through the assistant panel's Assistants tab.
7. **Edit Lead "paste and fill"** is the Edit-with-AI card on `/leads/:id/edit` (type or speak the change, the form fills); the Add Lead paste box is not shown on edit, as M2 built it.
8. **Assistant docking.** The panel docks only from 1920 px (1920 − 248 sidebar − 440 panel ≈ 1230 px of page). Below that it overlays with a backdrop, so no page grid gets squeezed (M7 R5). Container-query layouts were not attempted.
9. **Stage renames apply to every language.** An admin types one label; it replaces `catalogue:stage.<key>` and `stageShort.<key>` in English and Tamil. Clearing the label restores the catalogue names.
10. **Automatic task titles** stay stored in English (data), and task rows show them translated through `domain:task.autoTitle.<reason>` when the task has an `autoReason` and a lead.
11. **Activity log coverage.** Task edits / reschedules / reopen / delete and appointment edits / confirm / delete now emit events (`task.updated`, `task.deleted`, `appointment.updated`, `appointment.deleted`). Removing a client logs `lead.updated` (fields `clientId`) on the lead. Notification read/unread, saved views, drafts and mapping profiles stay unlogged (personal UI state or import housekeeping).
12. **Manager rule guard.** Managers cannot change company-wide or other teams' assignment rules in the services (not just the UI). The auto-assign switch and the per-executive cap remain company-wide settings managers may change, with the existing UI warning (M8 assumption 4).
13. **`/__kit` removed.** The dev-only component gallery, its `kit` namespace and the unused `StubPage` / `common:comingSoon` keys were deleted; it was never in the nav or the production router.
14. **Booked / Sold from the property form asks first** (same wording as the bulk confirm); Booked / Sold in the list's bulk menu asks first; both still offer Undo afterwards.
15. **Lead page grid on phones.** The page grid's single phone column is pinned to `minmax(0,1fr)` (and the asides to `min-w-0`), so a wide card (the follow-up assistant added in Phase 3) cannot widen the page past the screen. Before this, LEAD-1001 measured 552 px on a 412 px phone, and the assistant panel's Close button could not be tapped. Regression check: `e2e/integration.spec.ts` "@phone the lead page … fits the phone width".
16. **M7 e2e after the overlay change.** Below 1920 px, following a link from the assistant closes the overlay (as it always did below the old 1280 px threshold), so `e2e/m7-ai.spec.ts` reopens the panel after the "open the changed record" link.

17. **Reassignment and the old owner's Today (suite owner).** After a lead is reassigned it leaves the old owner's priority list, but a visit the old owner already did today ("Needs outcome") stays on their Today appointments, because E3 moves only open tasks and future appointments: the person who ran the visit records its outcome. `e2e/integration.spec.ts` checks both Todays through the priority list for that reason.
18. **§7 journeys in `e2e/integration.spec.ts` (suite owner).** Site visit from a lead page (appointment + timeline + stage + calendar + reload), booking on the pipeline (property booked, client created, gone from matching), reassignment (both Todays, history, timeline, both notifications), a pipeline move reaching the manager Today and Reports (aging table), and persistence + Reset demo data. All read the persisted store as well as the screen.

## Visual unifier (Phase 3)
- KPI cards are one shape everywhere: `KpiCard` is a full-height flex column, the label row has a fixed minimum height, the ring sits beside the value (it used to sit in the label row and squeezed the label to "OVERD… FOL…" on phones), and the sparkline / target bar sits on the card's bottom edge so a row of cards lines up. Clickable cards are buttons, and buttons centre their content vertically; the flex column fixes that, so the per-page `className="flex flex-col justify-start"` work-arounds (Activity, Notifications) are gone.
- A KPI without a chart shows its own icon large and faint in the corner (decorative, `aria-hidden`, tone colour at 7% / 12% in dark). Chosen over inventing data for a sparkline.
- One style for the page-header AI action next to the single primary button: new Button variant `ai-outline` (AI border + AI text on the card colour). Applied to Leads "Paste a message", Tasks "Follow-up assistant", Appointments "Paste & book" (header + empty state), Team "Team insight", Properties "Paste a listing" (was a ghost button) and Notifications "Catch me up" (was a filled AI button, a second primary next to "Mark all read").
- Today priority rows use a container query (`@3xl`, i.e. about 690 px at the 90% desktop root size) instead of the viewport `sm` breakpoint: in the 2-column desktop layout the list is about 615 px wide, and the side-by-side row clipped names ("Karthik Subram…") and broke reason chips over two lines. Narrower lists stack: name, reason and due on top with the score ring on the right, actions on their own line.
- Matching "Fresh matches to send" rows carry the buyer's avatar, the property icon and a match ring instead of a bare percentage.
- One keyboard focus ring for plain links and buttons that draw none of their own (`:where(...)` with zero specificity in `index.css`, so component focus styles still win).
- FilterBar keeps the search box at its width on desktop (`lg:shrink-0`); in Tamil the filter pills squeezed it to one word.
- e2e `m1-today-reports` "list re-ranks" step compared row names; one lead can own two rows (Ananya Iyer: the 15:00 call and an overdue follow-up), so from about 13:00 the test failed whatever the layout. It now checks the rescheduled row's item id.
- Screenshots: `notes/screens/final/<route>-<role>-<width>-<theme>.png` (16 routes × admin/manager/executive × 1440 light, 1440 dark, 768, 375; routes a role cannot open are skipped). "Before" shots of the old app are in `notes/screens/before/` (wireframe-rebuild on 5180: Properties, Property, Leads, Lead, Settings, and its Sales dashboard placeholder; Leads and Properties also at 375).
